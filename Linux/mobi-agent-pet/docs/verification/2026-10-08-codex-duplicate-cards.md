# Codex 会话卡片重复：调查与修复

日期：2026-10-08

## 用户现象与调查结论

用户确认重复发生在「桌面宠物 → 概览」下方会话卡片，额度区并未重复。此前的 Claude 修复处理启动恢复 ID 与 HTTP 事件 ID 不一致；Codex 本次有另外的日志身份与展示问题。

对当前机器的三个相关 Codex JSONL 文件做只读检查与生产监听器回放，确认：普通日志与带额外 UUID 后缀的桌面版日志副本具有相同 `session_meta.id`，而后台子代理具有独立 ID、`source.subagent.thread_spawn` 及 `parent_thread_id`。

## 根因

1. 本机、远程日志监听器按文件名最后五个连字符片段拼接 ID。遇到 `rollout-时间-原会话UUID_副本UUID.jsonl` 时，结果混入原 UUID 最后十二位和副本 UUID，产生并非真实会话的伪 ID。Hook 的另一套解析规则会得到不同 ID。
2. 概览直接展示完整快照，忽略 `headless` 与 `hiddenFromHud`；后台子代理、已被同进程新会话替代的记录也显示为普通用户会话卡片。此前页面去掉了内部来源标签，更容易将这些记录看作重复。
3. 本机监听缓存淘汰后，读取位置可以仍然保留，重新接入从旧偏移继续读取，跳过文件头。这会丢失元数据会话身份和子代理角色，使后台记录再次被识别为普通记录。

## 修复

- 将 Codex 身份解析集中到既有 `hooks/codex-session-index.js`。优先使用 `session_meta.id`；缺失时按明确的日志文件格式解析；最后使用事件提供的 ID。支持 POSIX 与 Windows 路径，处理桌面版 UUID 后缀。
- 官方状态/审批 Hook、本机监听、远程监听及远程等待输入恢复使用同一规则。共享 helper 已包含在 SSH Hook 部署清单中。
- 本机重新接入保留缓存的逻辑 ID，并从有大小上限的文件头恢复身份、来源和子代理角色；不会从头重放历史事件。
- 概览沿用 HUD 可见性规则：后台、睡眠及被替代的记录不绘制普通卡片；数量、宠物工作提示和别名编辑生命周期使用同一筛选。内部状态与后台记录仍可被系统正常处理。
- 真实的不同元数据会话 ID、不同远程配置保持独立；不会按应用名称、工作目录或共享进程号将桌面版的多段对话合并。

## 验证

新增 9 个回归用例，分别覆盖 Hook 路径、普通/带后缀日志的一致身份、真实不同会话、缓存淘汰后恢复角色、后台卡片与空状态，以及远程正常监听和等待输入恢复。相关用例在修复前按预期失败，修复后通过。

使用同一组真实日志只读回放，修复后输出两个相同的用户会话 ID，以及一个 `headless=true` 的子代理 ID；去重后只有一个可见用户会话，未再生成混合 UUID 的伪 ID。没有修改用户日志或历史数据库。

完整 `npm run test:phase2` 退出码为 0：业务测试 296 项、界面测试 79 项、桌宠运行时测试 6349 项通过，共 6724 项；22 项按原有条件跳过。类型检查、构建和 `git diff --check` 通过。独立代码复核发现远程解析遗漏，补齐并验证后无剩余 Critical / Important 问题。
