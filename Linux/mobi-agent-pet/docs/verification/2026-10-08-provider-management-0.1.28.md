# 供应商管理 0.1.28 验证记录

日期：2026-10-08。源码基线与许可见 `../third-party/cc-switch-provider-source.md`。

## 本轮交付

- 共存型供应商可指定原生配置标识；实际使用的标识保存在 `provider_enabled.native_key` 中。
- 数据库 v7 → v8 将既有启用记录的内部 ID 保留为原生标识，避免升级后移出错误条目。未加入的记录不删除磁盘条目；未管理的同名条目即使配置相同也阻止加入。
- 获取模型后写入 OpenCode、OpenClaw、Hermes、Pi、MCode 的原生模型列表，Claude Desktop 写入模型路由。重复选择不会增加重复项。
- Codex 表单按 `model_provider` 指定的路由修改接口；Grok 原生 `[model.*]` 配置可以在常用字段中修改模型、接口与凭据。
- 公共导出保留原生配置标识与 Hermes `api_mode`，Codex/Grok TOML 经解析后仅导出明确的公开连接、模型和协议字段。凭据、请求头与未知字段不导出。

## 仍需移植的能力

当前版本尚未达到 CC Switch 添加供应商表单的完整移植标准。后续继续依据已确认的设计推进，不把原始 JSON 编辑入口视为完整专属表单的替代。

1. 预设 `templateValues` 变量输入与替换、预设类别和附加选项的完整表单。
2. 请求头、额外选项，以及 Pi 等工具的专属高级字段编辑器；当前已存在的标量字段可以逐项编辑，新增复杂字段和 null 类型仍需完整 JSON。
3. 按 Agent/API 协议处理模型查询；目前后端查询仍按 OpenAI `data[].id` 响应处理。
4. Claude Desktop 的完整直连路由编辑、通用供应商的专属模型角色编辑界面。
5. 与 CC Switch 原有导入格式的兼容；当前支持 Mobi 公开配置 JSON 导入导出。

本地代理、跨协议转换与依赖代理的 OAuth 中心已被确认设计排除；相关预设保留“暂不能启用”的状态。

## 执行决定

- 沿用当前工作区的既有未提交开发内容，不创建从 HEAD 出发的新工作树，避免遗漏尚未提交的供应商模块。
- 使用独立 `native_key` 保存实际写入标识，不根据编辑后的名称猜测已启用条目的位置；迁移只更新数据库，不重命名 Agent 磁盘配置。
- 默认导出继续只含公开字段；TOML 在主进程解析和投影，不能直接导出原文。
