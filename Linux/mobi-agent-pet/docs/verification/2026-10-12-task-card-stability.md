# 任务卡片停留与双击容错

用户随后明确选择 5 秒自动收起，并保留外部点击收起。当前最终停留规则见 [任务卡片 5 秒自动收起](2026-10-12-task-card-auto-dismiss.md)；本报告的双击容错、手势隔离和拖拽修复继续生效。

## 用户要求与原因

用户反馈卡片数秒后消失，双击时轻微晃动又被当作拖拽，需要连续多次点击才能打开。

旧 HUD 鼠标离开宽限为 500ms；上一轮补充了显式收起，但保留该旧宽限，所以等待或鼠标移开仍能自动关闭。拖拽旧门槛仅 3px，主进程在越过门槛前已移动窗口；输入层使用 client 坐标，窗口位置或尺寸更新也会改变坐标。仅依赖原生 dblclick 不能覆盖这些情况。

## 最终规则与实现

- 双击打开后持续显示，不按等待时间或鼠标离开关闭。点击外部、真正拖拽、显示资格失效才收起；固定卡片规则保留。
- 前端与主进程共用 `pet-input-policy.js`：拖动门槛 8px。在门槛内保持桌宠窗口位置不变；超过后按原锚点正常移动。
- 输入层使用 screen 坐标，避免窗口更新制造虚假位移。增加独立于 held 和旧反馈计数的点击对（500ms、12px），原生 dblclick 继续兼容系统间隔，并与点击对去重。
- 实际拖动结果带 gesture ID 同步，旧 ID 不影响下一次按下；松手后主进程保留本次真正拖动的结果，拒绝由迟到或缺失 pointermove 产生的错误展开请求。
- 合法的新按下先清除旧点击结果，再独立检查 held 授权。因此禁止 held 的自定义模式仍能双击打开卡片，不获得移动或提起权限。
- Ctrl/Meta 修改点击、进入迷你/免打扰、取消和真正拖动打断点击对；普通 held 和状态更新不打断。会话跳转、额度环、模式门禁及低功耗清理保持原规则。

## 验证

- 回归修前失败，修后通过：30 秒等待/鼠标移开保留、5px 抖动双击、screen 坐标稳定而 client 坐标变化、阈值前不移动、慢点击及拖动隔离、修改点击和 mini/DND 穿插。
- 针对性审查发现并修复：主进程拖出再回原点而 renderer 没收到 pointermove 时误展开；修改点击/模式穿插保留旧点击对；旧拖动结果阻止禁止 held 的自定义模式打开卡片。
- 相关回归 173 通过；`npm run test:phase2` 最终 6862 通过、22 跳过、0 失败，包含 manager 类型检查和构建。
- 完整 AgentLog 主程序的隔离实例使用真实 Electron 输入窗口与原生 HUD 窗口。空闲、工作、等待、漫游各用两个 clickCount=1 点击并加入 5px/4px 抖动，均只展开一次，桌宠位置不变；鼠标移开等待 10 秒保留；点击外部、真正移动 +70/+35 收起，拖拽仍保持 held。
- 故意拦截 `hit-drag-started`：主进程轮询驱动拖出 30px 再回原点，随后松手，卡片不误开；补发旧 ID 后两次新点击正常展开。之后实际保存禁用 held、启用 HUD 的自定义配置，仍能双击展开，drag lock 保持 false。
- 最新原生日志 `CARD_STABILITY_PASS`，退出码 0；输入使用受控全局坐标/按钮状态，不操作用户鼠标，不修改用户配置或会话。实体平台验证为当前 Linux 原生窗口，其他平台未做实体鼠标验收。
