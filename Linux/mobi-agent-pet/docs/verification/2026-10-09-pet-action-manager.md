# 七状态动作管理

用户确认以七个可见状态管理桌面宠物动作，并增加按住人物立即提起的交互。

| 可见状态 | 对应事件与默认动作 |
| --- | --- |
| 空闲 | 待机、打哈欠、打瞌睡、躺下、睡眠、醒来；默认随机播放 |
| 漫游 | 漫游、走动 |
| 工作 | 思考、执行工具、协作、清理上下文、搬运；默认仅一个工作动作 |
| 等待 | 提问、通知、等待确认 |
| 完成 | 完成提醒与庆祝 |
| 错误 | 运行错误 |
| 被提起 | 按住人物即进入，不需要先移动；松开恢复最新 Agent 状态 |

## 使用

进入「桌面宠物 → 动作管理」，七个状态在同一画布中展示。动作卡片可以直接拖入另一个状态，或拖到同状态卡片前排序；底部动作库可拖入任意状态（复制添加）。鼠标悬停时显示上移、下移和移出图标，卡片角落的状态选择框提供键盘操作。每个状态的两个图标选择顺序或随机，每个动作保留 0.5–60 秒输入；不用的动作直接拖回动作库，需要时再拖入状态。右上角可展开为全屏画布；不支持全屏时拓宽当前内容区。

修改后点击「保存并应用」。配置按主题保存，Mobi A / B / C 可分别安排动作。未保存动作方案的主题继续使用原有播放逻辑。恢复默认会更新当前草稿，仍需保存。至少保留一个启用的空闲动作；其他状态可留空，继承空闲的动作及播放方式。迷你模式沿用原有动作。

## 行为与实现

- 展示分类合并，不改动 Agent 内部状态、会话检测与权限确认。工作子事件变化不会重置同一工作动作队列。
- 顺序播放跳过停用动作；随机播放避免连续选中相同动作；单个动作按所设间隔重播。
- 完成和错误为一次展示：顺序播放完整一轮，随机播放一个选中动作，随后恢复运行状态。空槽回退同样使用有效空闲槽的模式和时长，避免提前截断。
- 提起期间保留最新 Agent 事件，释放时恢复。未保存方案的旧主题继续支持左右拖动资源。
- 动作切换同步真实点击范围，保持逻辑状态与会话生命周期；帧 IPC 校验窗口发送者、当前状态及主题中的启用资源。
- 偏好写入走现有设置控制器，保留主题声音及点击范围覆盖。保存期间切换主题不会将旧结果显示为新主题保存成功。
- 轮播帧不刷新省电模式的活动时间；到达原有空闲期限后暂停动作计时，收到活动时恢复。
- A / B / C 的提起动作改为双臂上举、躯干悬空，并以头部附近为轴轻摆。静态对比见 `2026-10-09-mobi-held.png`。

## 开发版加载失败排查

实机主进程启动于 08:43，而动作数据接口更新于 09:42，页面资源更新于 10:01。开发版的单实例锁会让再次启动的进程退出并唤起已有进程，因此新页面可能调用仍在内存中的旧接口，返回数据缺少 `actionManagement`，原先显示重复的「动作加载失败」。

页面已区分正在加载和加载错误；旧接口数据会明确提示从托盘完全退出后重启，并提供重新加载入口。增加旧响应回归测试，以及真实 Mobi C 主题经过主进程数据构建直接进入 JSDOM 页面的一体化测试，避免只测试手写响应。此次相关 19 项测试通过，0 失败，`git diff --check` 通过。未操作用户应用的退出或重启。

- 从状态拖出是移动，从动作库拖入是复制；已有同文件的目标不接受重复添加，保留源卡片配置。

## 用动作库控制是否使用

启用开关已移除。状态框只显示参与播放的动作，卡片拖回底部动作库即可从该状态停用；需要时再从动作库拖入状态。状态移动下拉框提供「动作库」选项，原移出图标也使用同一条回库路径。动作库仍是当前主题的完整素材目录，可以把同一素材用于不同状态。

为兼容已有 v1 配置，内部保留 enabled 标记和停用动作的时长元数据，不新增状态或更改播放模型；旧配置的停用动作从状态区收起，重新使用时优先恢复该状态的时长，其次恢复已有停用记录的时长。移动到旧停用占位记录时替换占位，避免重复文件。排序仅作用于可见动作，跳过隐藏记录。空闲仍必须保留一个播放动作。操作修改草稿，保存后生效。

- 先由回归测试复现开关仍显示、动作库不能接收拖回卡片及旧停用动作显示问题，再实现修复。

## 原生动作时长与角色表演

用户进一步明确：卡片名称和时长合为一行，不提供秒数设置；保留顺序、随机、排序和回库。三个角色为方头莫比（认真加班、努力补救）、圆头莫莫（咖啡续命、打盹摸鱼）、扁方头比比（急性子、炸毛后继续赶工），都围绕苦命打工人的搞笑表演设计。原生完整动作必须严格超过 3 秒，按 4、5、6 秒设计。

用户随后确认每个原生动作必须可循环，并纠正工作素材混入错误剧情的问题。工作和小窗工作应始终能看到双手在正常电脑上敲键盘，性格通过力度、节奏和表情表现；错误的摔物、报错、冒烟不能混入工作表演。默认动作保持状态含义，用户仍可自由跨状态安排动作。

主题提供按文件声明的 `actionDurations` 和中文 `actionLabels`。页面、渲染器、主进程状态及动作帧 IPC 均使用同一自动时长；旧 v1 方案继续保留动作分配、启用和播放模式，但旧手动时长不再控制播放。时长元数据缺失或非法时使用 5 秒。迁移不会原地修改已有设置，拖拽编辑并保存后写入自动时长。

初始回归验证秒数输入仍可编辑、原生时长未生效；随后补充实际主进程 IPC 回调测试，复现旧短时长导致随机完成动作无法按选中动作时长返回的问题，统一后通过。有关随机/顺序、旧配置、跨状态移动及空闲保底的专项验证已覆盖。
