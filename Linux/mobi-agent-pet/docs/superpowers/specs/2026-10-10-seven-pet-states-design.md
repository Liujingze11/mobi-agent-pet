# 桌宠七状态逻辑统一

日期：2026-10-10

状态：用户已确认设计，正在编写实施计划；尚未修改产品代码。

## 用户要求与验收目标

桌面宠物只有七个状态：空闲、漫游、工作、等待、完成、错误、被提起。每个状态包含可自由分配和替换的动作。动作不能重新成为额外的逻辑状态。

本次先统一这套模型及所有桌宠入口，之后再逐项讨论常规、后台、自动模式。此次不决定自动模式应关闭哪几个状态。

验收标准：

- 桌宠控制器、渲染器、输入窗口和桌宠 IPC 的状态值始终属于同一套七状态枚举。
- 默认配置与动作管理里展示的配置一致，不需要先点击保存才能进入七状态播放模型。
- 已保存的动作分配、顺序/随机选择、按主题保存规则、素材原生时长继续生效。
- 任一播放入口都不能选取当前状态有效动作槽以外的素材。
- 正常显示和贴边显示使用同一逻辑状态及同一动作方案。
- 提起期间继续接收并记录 Agent 事件；释放后恢复最新任务状态。
- 重载主题、恢复窗口、切换模式、低功耗暂停/恢复不引入额外状态，也不产生重复播放器或遗留定时器。
- Agent 会话检测、事件记录、统计、权限协议和终端跳转保持现有语义。

## 排查证据

1. `src/pet-action-plan.js` 已定义七状态，`groupForState()` 已把旧名称映射到七状态。但这是播放层分组，`state.js` 的 `currentState`、状态优先级、计时器、对外 getter 和 IPC 仍直接使用旧名称。
2. 对真实 `state.js` 执行只读探针，`applyState("thinking")` 返回 `thinking`，其他旧状态同样直接进入 `currentState`；贴边时工作变成 `mini-working`。发送给渲染器的状态仍是这些旧值。
3. `theme-context.js` 只读取已经保存的 `actionPlan`。动作管理数据接口生成 `defaultPlan()`，运行时未保存时却得到 `null`。真实 Mobi A 默认工作槽只有 `working.svg`，旧运行时仍可能选择 `thinking.svg`。
4. `renderer.js:playReaction()` 停止配置播放器后直接播放传入文件。点击、连击和文件拖入反馈因此能绕过动作分配。
5. `mini.js`、`state.js`、`tick.js`、`main.js` 在贴边入场、探头、工作、等待、完成、睡眠和重载时创建 `mini-*` 状态。`groupForState()` 对这些名称返回空，播放器直接回退到传入素材。
6. `tick.js` 的鼠标静止逻辑和 `state.js` 的睡眠计时器仍驱动 `yawning → dozing → collapsing → sleeping → waking`。睡眠动作已经属于空闲组，这套额外状态链应退出桌宠逻辑。
7. `settings-animation-overrides-main.js` 的旧预览接口直接执行 `applyState(stateKey, file)`；它也能绕过当前状态动作分配。
8. `theme-schema.js` 仍要求 `thinking`、睡眠系列以及小窗系列资源绑定；`state-visual-resolver.js` 和部分几何代码按旧状态推断素材或显示形态。
9. `app-mode.js` 控制旧等待/完成动画开关，没有使用七状态契约。此处应连接统一契约，但不在此次增加新的模式产品规则。

此前《七状态动作管理》说明明确保留了未保存方案和迷你模式的旧行为。因此这次是在用户新要求下收拢兼容路径，不把所有旧内部名称都当成历史 bug。

## 方案选择

推荐：建立桌宠独立的七状态控制层，在 Agent 事件与桌宠之间完成映射，所有桌宠播放走一个有效方案。

仅在界面或 getter 返回值上改名不足以解决隐藏入口、旧计时器和配置绕过问题，不采用。

把 Agent 会话、上报协议和历史事件也全部改成七状态会扩大本次范围，并损失会话细分信息，不采用。

## 唯一状态契约

| ID | 中文 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `idle` | 空闲 | 无活动任务，或回落到空闲 | 新任务、等待、错误、漫游或提起 |
| `roam` | 漫游 | 桌宠实际开始自主移动 | 移动结束/取消、任务变化或提起 |
| `working` | 工作 | 思考、执行工具、协作、上下文维护等任务活动 | 等待、完成、错误或任务结束 |
| `waiting` | 等待 | 仍需要输入或确认的请求 | 请求解决、取消或任务继续 |
| `complete` | 完成 | 已确认的一轮任务结束 | 完成展示结束，或新任务/等待/错误 |
| `error` | 错误 | 已确认的运行错误 | 错误展示结束，或任务继续/等待 |
| `held` | 被提起 | 输入窗口确认按住并提起 | 松开、失去捕获、窗口失焦或操作取消 |

用户把某个素材安排到其他状态时，素材文件名称和画面内容都不改变该状态的逻辑含义。

统一模块提供不可变枚举、合法性校验、旧输入映射和七状态优先级。页面、主进程和渲染器共享该模块；不能各自维护一份白名单。

### 旧名称仅作为边界输入

- `thinking`、`juggling`、`sweeping`、`carrying` → `working`。
- `notification` → `waiting`；`attention` → `complete`。
- `yawning`、`dozing`、`collapsing`、`sleeping`、`waking`、`dizzy` → `idle`。
- `drag` → `held`。
- 旧 `mini-*` 输入在兼容入口按含义映射；小窗入场/探头不是新的业务状态，几何变化结束后仍恢复同一个任务状态。
- 无法识别的状态输入不改变桌宠，记录诊断信息。禁止把任意字符串写入桌宠状态或 IPC。

Agent 的原始事件、历史会话记录和旧主题素材元数据可以保留旧名称。它们是输入或资源描述，不能作为正在运行的桌宠状态。

## 控制器与任务解析

桌宠控制器拥有 `currentState`、最新任务状态、提起锁、短暂完成/错误展示及其定时器。渲染器不再独立持有一个与主进程不同的被提起状态。

先按现有 Agent 会话规则解析真实任务，再将结果映射到七状态，最后由桌宠控制器处理展示和互动优先级。现有 headless 排除、重复 Codex 会话排除、完成防抖、权限持有与会话清理继续沿用。

- `held` 是显示覆盖：任务变化更新待恢复状态，不抢走提起画面；释放后立即解析最新状态。
- `error`、`waiting`、`complete`、`working` 的冲突在七状态层处理；工作细分事件不再靠不同桌宠优先级抢占同一工作槽。
- 只有完成、错误需要一次展示及展示结束后的恢复机制。上下文清扫和搬运不再作为独立的一次状态控制返回计时。
- 完成展示仍由已确认完成事件触发，不能把任意工作子事件误认为完成。
- 权限是否自动批准继续由原权限桥决定；状态统一不会自动替用户作出更多决定。

## 默认与已保存动作方案

增加一个有效方案入口：优先读取合法的已保存方案，否则构建主题默认七状态方案。动作管理、主题上下文、主进程时长、渲染播放器及帧校验必须读取同一结果。

- 默认方案从启动起就生效，不写入偏好、不要求用户保存。
- 空闲至少有一个有效动作。其他槽为空时继续使用空闲槽的动作及播放方式，逻辑状态仍是原状态。
- 工作默认一个工作动作；保留用户已保存的跨状态分配。
- 顺序播放使用启用动作的顺序；随机播放避免连续重复；所有时长由主题的原生时长规则解析。
- 完成/错误展示与当前有效槽保持一致：顺序完整一轮，随机一个动作。新任务可中断已经失效的展示。
- 旧 v1 保存方案保持可读，不原地改写用户的动作分配。

## 互动、鼠标静止与预览

- 提起事件走主进程状态控制器，播放 `held` 槽；释放时恢复最新状态。
- 点击、连击、文件拖入不能再直接传入素材文件和时长播放。原有打开菜单、打开项目终端等操作可以保留；视觉反馈只能使用当前七状态的配置，不增加隐藏反应状态。
- 鼠标静止不会再进入额外睡眠状态。打哈欠、睡眠、醒来等素材是否出现，完全取决于它们是否被用户安排在空闲槽以及该槽的播放方式。
- 移除鼠标绕圈触发独立 `dizzy` 状态的路径。
- 低功耗作为播放器暂停/恢复机制保留，不通过新增或伪装状态实现。轮播帧不能刷新用户活动期限。
- 动作管理卡片继续在隔离预览中播放。旧接口不能再把任意素材注入桌宠；兼容调用明确返回该预览路径已停用，并引导使用动作管理预览。

## 贴边显示

贴边是一种窗口显示形态，不是一套状态机。

- 保留窗口位置、尺寸、裁切、跨屏边界、探出/收回和退出逻辑。
- 正常与贴边显示共用七状态和有效动作槽；进入贴边不能把工作任务变成空闲，也不能重置同组动作队列。
- `mini-*` 专用素材可以继续作为已有资源存在，但不得由小窗路径绕过动作方案自动播放。它们不会增加状态管理栏目。
- 视口、镜像和命中几何通过显式显示形态参数处理，不再用 `state.startsWith("mini-")` 判定。
- 入场/退出期间使用几何过渡标志避免窗口并发定位；这类标志不成为状态，也不能长期屏蔽真实任务更新。

## 主题加载与旧格式兼容

在加载边界解析旧主题里的细分资源绑定，并生成七状态有效动作方案。原始配置可保留用于导入兼容、素材目录和诊断，但活动桌宠的状态定义只暴露七个 ID。

主题校验区分旧格式输入与规范化的七状态输出：旧格式仍可导入；新七状态格式不要求声明 `thinking`、睡眠或 `mini-*` 状态。素材、声音、点击范围和来源校验保留。

内置 Mobi A/B/C 的默认动作和已有保存方案需要在迁移前后逐项比较，避免丢动作、丢播放模式或错误地用另一个主题的素材。

## 模式和重载

模式规则连接七状态契约，继续保留当前声音、气泡、权限和完成提示行为。此次不添加自动模式的新状态取舍，不改变已经保存的动作方案。

后台隐藏/DND、返回常规、进入自动、主题切换、窗口重载都通过控制器恢复合法七状态。后台无需创建睡眠状态。等待提示被模式抑制时，显示回落到其他活动任务的工作或空闲；任务等待事实仍保留。

## 文件边界

- 状态契约：新增共享七状态模块；`pet-action-plan.js` 使用它定义分组、有效方案和播放器输入。
- 桌宠控制器：新增小型控制器；`state.js` 保留 Agent 会话解析，桌宠展示接口委托控制器。
- 主题/资源：`theme-context.js`、`theme-schema.js`、`theme-loader.js`、`state-visual-resolver.js`、动作管理数据接口统一有效方案和旧格式适配。
- 主进程/互动：`main.js`、`pet-interaction-ipc.js`、`hit-renderer.js`、`preload.js` 更新状态与提起 IPC、帧校验、恢复路径。
- 播放/显示：`renderer.js`、`tick.js`、`roam.js`、`mini.js`、`hit-geometry.js` 去除隐藏状态路径，保留显式显示形态和移动保护。
- 相关消费者：托盘、主题重载、旧预览、几何和省电接口改用规范状态；会话页面继续展示 Agent 原始会话信息。

## 必要验证

先建立能够暴露现状的回归测试，再修改实现：

1. 任意旧事件经过真实入口后，getter、观察器、渲染 IPC 和输入窗口 IPC 只出现七状态。
2. 未保存方案、恢复默认、切换角色都立即按相同七状态方案播放；没有旧状态播放器回退路径。
3. 同一个工作槽内思考/执行/协作事件变化不重启动作队列，不创建清扫/搬运短暂状态。
4. 鼠标静止、绕圈、点击、连击及文件拖入不能播放未分配素材或新增状态。
5. 提起时收到工作/等待/完成/错误事件，释放、失焦、捕获丢失及主题重载后恢复正确且不残留提起锁。
6. 贴边工作、等待、完成、错误都保持七状态；正常/贴边转换、探头及跨屏布局不丢真实任务状态。
7. 完成/错误的顺序和随机播放、空槽回落、有效时长、任务抢占及计时器清理正确。
8. 有效方案统一帧校验：拒绝外国窗口、状态不匹配、未分配文件、旧时长和旧主题迟到回包。
9. 低功耗暂停、系统唤醒、主题/渲染重载都只启动一个播放器，并保持状态与命中范围同步。
10. 新格式七状态主题和旧格式主题均能加载；已保存方案、素材分配、声音和命中范围不丢失。
11. Agent 会话、权限桥、完成防抖、Codex 去重、记录和计时现有专项回归通过。
12. 最后运行 `npm run test:phase2`；修改主题配置时运行三款主题校验；静态审查桌宠状态赋值和 IPC 入口是否还有绕过路径。

原生透明窗口、拖动和跨屏定位的观感需要桌面实机验证；自动化验证不能声称已经覆盖这些原生行为。
