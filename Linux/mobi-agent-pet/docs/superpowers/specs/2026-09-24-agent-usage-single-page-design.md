# Agent 使用情况单页设计规格

日期：2026-09-24
目标版本：0.1.2

## 目标

“应用界面”是一张供用户回顾 Agent 工作情况的页面。它借鉴 iPhone“屏幕时间”的信息顺序、浅色分组卡片、日／周柱状图和逐层查看方式，并适配现有桌面宽窗口。用户在同一页回答四个问题：今天或本周 Agent 实际活跃多久、用量和预估费用是多少、时间分布在哪些项目、每段完整会话发生了什么。

这里的“会话”是 Agent 从会话开始到结束的完整对话，不是单条消息。页面不新增主导航或独立详情页。点击项目只更新当前页的筛选状态；点击会话在当前页右侧展开详情。

## 页面结构

页面保持一个垂直滚动区域，按以下顺序显示：

1. **总览**：日期切换、今天／本周切换、突出显示的 Agent 活跃时间，以及与上一日／上一周的变化。今天显示 24 个小时柱，本周显示 7 个日期柱。图表当前选择的时间段有清晰高亮，键盘也可以访问每根柱。
2. **用量摘要**：完整会话数、输入 Token、输出 Token、缓存 Token 和预估费用。费用单位为 USD，显著标注“按公开 API 价格估算”；订阅费用不在其中。只得到部分模型价格时显示“部分估算”和覆盖会话数；没有可靠用量或价格时显示“暂无数据”，不写 0。
3. **项目分布**：按活跃时间排序的项目列表及横向比例条，包含“未归类”。选择项目后，项目列表保留在原处，下面的完整会话列表按该项目筛选，并提供“查看全部”恢复入口。
4. **完整会话**：沿用现有的来源、状态、项目和日期筛选能力；每行显示标题、Agent、项目、开始时间、活跃时长、Token 和费用状态。选择一行后，右侧详情显示开始／结束、完整跨度、活跃时长、模型用量、费用估算依据及项目归属。小窗口中详情在列表下方展开。

视觉使用浅灰蓝背景、白色卡片、细分隔线、黑色文字和克制的蓝色主色。图表及项目色只承担数据区分，不依赖颜色传达唯一信息。桌面宽度用于增加阅读空间，不仿造 iPhone 外壳。

## 时间统计口径

- “Agent 活跃时间”来自现有 `agent_active_intervals`，按用户本地时区切分。正在运行的区间截到查询时刻；跨日区间分别计入对应日期。
- 总览时间对并行 Agent 区间取并集：同一现实分钟只计一次。会话详情的活跃时长则是该会话区间之和；其完整跨度为结束时间减开始时间，两者明确分开。
- 项目比例图把并行区间的重叠时间平均分配给同时活跃的项目，使项目份额之和等于总览活跃时间。每个项目的会话详情仍显示各会话真实活跃时长。
- “本周”按本地周一至周日计算。比较上一日／上一周时使用同样长度的时间窗口；若历史区间缺失，显示“暂无对比”。
- 完整会话数按在所选时段内出现活跃区间的不同会话 ID 计算。没有活跃区间的已记录会话仍可在历史列表中查看，不虚构活跃时间。

## Token 与费用来源

- 统计在本机可读取的 Codex 和 Claude Code 原生日志。解析在主进程的受限后台任务中完成；渲染进程只接收聚合数字、模型名、覆盖状态和错误状态，不接收原始对话内容。按文件路径、大小和修改时间缓存解析结果，文件变化时增量更新。
- Codex 按会话解析 `token_count` 的累计 `total_token_usage`，利用相邻记录的差值计入记录时间；计数回退时按新计数开始新段。读取输入、缓存输入、缓存写入和输出字段，避免把 `last_token_usage` 当作整段会话总量。只映射本机可确认的会话日志；远程或缺失文件显示“暂无数据”。
- Claude Code 按会话解析 assistant 消息的 `usage`，以消息 ID 去重，避免流式更新重复计数。读取输入、缓存读取、缓存写入和输出字段；排除标记为子 Agent、跨会话或 API 错误的消息。没有稳定消息 ID 的记录单独标记为覆盖不完整。
- Token 发生时间用于日／周统计；无法确定时间的记录只用于会话总量，并标记时间分布不完整。旧会话能回填多少取决于原始日志是否仍在本机，缺失时保持未知。
- 费用是每种模型对应 Token 类别乘以版本化价格表的 **API 等价估算**。价格表记录模型 ID、费率、适用日期和官方来源；不认识的模型、通过代理使用的模型和未知价格不参与金额求和，也不显示为零费用。模型切换的会话分别计价。用户看到价格表日期和估算覆盖率。

## 项目归类

现有工作目录／worktree 自动匹配继续作为默认归类。会话详情允许用户手动选择项目或“未归类”。手动选择在数据库事务中更新该会话、对应活跃区间和相关统计归属；新增持久化的手动归类标记，后续自动匹配不得覆盖。项目被归档后，历史会话仍保留归属和统计。人工计时的既有数据保留在数据库，不混入 Agent 活跃时间或 Token 统计。

## 接口与状态

- 新增一个按 `day`／`week` 与日期查询的统计接口，返回图表桶、总时长、项目份额、会话数、Token 和费用覆盖状态。查询直接使用相关日期范围内的数据库区间，不能依赖当前会话列表的 500 条上限。
- 会话列表继续通过现有接口读取，并增加按当前日期和项目定位的能力。详情在本页展开；统计接口与列表使用相同的项目归类结果。
- 单个日志无法读取或解析时，时间和会话功能照常显示，用量卡片说明缺失范围；不会让整页进入错误状态。数据库不可用时继续显示现有错误与重试界面。
- 数据库迁移保留旧会话、项目和人工计时数据。只存储归类覆盖和必要的用量聚合／缓存元数据，不存储原始对话内容。应用界面保持中文和英文文案完整。

## 验收

1. 同一页可见时间趋势、用量、项目和完整会话；项目选择与会话详情不发生页面跳转。
2. 跨日及并发场景下，总览时间、图表桶和项目份额符合上述口径；会话活跃时长与完整跨度分别显示。
3. Codex 累计记录和 Claude 流式重复消息不会重复计数；日志缺失和未知模型显示“暂无数据”或“部分估算”。
4. 手动归类在新事件到来及重启后保持，并同步影响项目统计。
5. `npm run test:phase2`、类型检查与管理界面构建通过；在当前 GNOME 桌面实机查看单页。程序版本与更新记录升至 `0.1.2`。开发阶段不构建安装包。
