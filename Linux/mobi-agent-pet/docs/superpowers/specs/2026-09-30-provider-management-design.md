# Mobi 供应商管理与切换

## 目标与范围

在 Mobi 应用界面新增「供应商」页。用户可管理供应商，点击后切换 Agent 实际使用的 API 配置，并在桌宠空间看到当前供应商可查询的余额或剩余额度。供应商状态必须以磁盘上的有效配置为准，不能只改 Mobi 页面里的标记。

这一功能按可验证的阶段交付，每个代码交付阶段更新 Mobi 版本号：

1. 先完整移植 CC Switch 对 Claude Code、Codex、Gemini CLI、Grok Build、Claude Desktop、OpenCode、OpenClaw、Hermes、Pi 和 MiniMax Code 的「添加供应商」能力及全部预设：预设和自定义配置、各工具专属字段、通用供应商、表单校验、配置预览，以及表单内可用的连接或模型查询能力。新增的配置能够保存、编辑和删除。先保留这些能力，再由用户逐项决定删减；不预先精简添加表单。
2. 建立 Linux 上 Claude Code 和 Codex 的切换事务，然后依照 CC Switch 的不同配置语义接入其他八个工具的切换型或共存型配置；补齐排序和导入导出。Mobi 原本支持但 CC Switch 尚未提供切换适配器的 Agent 继续正常监测，不显示虚假的「可切换」操作。
3. 接入可用的余额或剩余额度查询，再提供受限的自定义查询规则，将结果按 Agent 和供应商准确展示在桌宠空间。

MCP、Skills、提示词、项目整套切换、云同步、本地代理、故障转移、跨协议转换及依赖代理的多账号 OAuth 认证中心不属于本功能。依赖这些模块的预设仍可查看和保存，但在依赖尚未实现时明确标为「暂不能启用」；不能伪装成已成功切换。Mobi 已有的主题、语言、开机自启和诊断入口继续使用现有设置；不复制 CC Switch 对应的设置页。供应商页仅设置与当前功能直接相关的配置位置、余额查询和恢复操作。

## 来源与移植方式

参考 CC Switch 的供应商表单、预设、配置投影、切换和用量查询实现，源代码基线固定为 `farion1231/cc-switch@482f57b335ff15e749893990a132a9e54e4eb8e2`。Mobi 保持 Electron、React、Node 与现有 SQLite 架构；将所需逻辑移植进 Mobi 的页面、主进程服务和 IPC，不启动第二个 CC Switch 窗口。复制的代码及实质性改写保留 CC Switch 的 MIT 版权和许可证声明，并在第三方声明中标出来源。

## 用户界面

应用界面顶部提供「使用情况 / 供应商」两页，沿用 Mobi 的蓝白配色和现有字级。供应商页先选 Agent，再显示当前供应商、其他供应商和「添加供应商」。卡片提供启用、编辑、删除、刷新余额；当前项有明确状态，正在写入时禁用重复操作，完成和失败都有可读反馈。添加流程移植 CC Switch 对所选工具提供的全部预设和表单字段，不预先删除高级字段；具体字段取决于所选工具及预设。未安装或暂不支持切换的 Agent 不提供启用按钮。

首次管理某个 Agent 时，先读取其现有配置并保存为可恢复的「当前配置」；绝不以空模板覆盖现有登录、Hook、MCP 或用户自定义字段。切换回官方登录时恢复该 Agent 的官方配置语义，不把第三方 API Key 留在有效配置中。界面提示该 Agent 是否需要重新启动才能让新配置生效。

## 数据与安全

Mobi SQLite 保存供应商 ID、Agent 类型、名称、预设标识、端点、模型、查询方式、创建及更新时间和当前项指针。API Key、访问令牌及包含凭据的备份不以明文进入 SQLite、渲染进程列表响应、日志或导出文件。凭据仅由主进程读取，使用系统安全存储加密；Linux 若退化为 Electron `basic_text` 或安全存储不可用，则拒绝持久化新凭据并给出清楚提示。导出默认剔除凭据，只有用户明确选择受保护的导出方式时才允许包含。

预设、账户余额和 Agent 额度是三类不同数据。余额记录金额与币种；套餐额度记录剩余量、单位和重置时间；Agent 自身的速率窗口继续沿用 Mobi 已有额度来源。主进程通过现有桌宠状态通道发布归一化结果。桌宠空间按 Agent 展示切换型工具当前供应商的数据；对共存型工具，按已配置的供应商分别展示，不臆测当前会话用了哪一个。所有结果标注数据时间；供应商不支持查询或查询失败时保留上次成功值并标为已过期，不显示猜测值，也不把金额换算为百分比。

## 实际切换流程

每个 Agent 有独立的配置适配器，负责识别现有文件、从预设生成目标字段、制作最小补丁、验证结果和提示生效方式。Claude Code 只修改其连接相关字段；Codex 处理 `config.toml`、`auth.json` 等相关文件。其他 Agent 的切换型或共存型语义由其适配器定义，不能套用 Claude 的写法。

主进程对同一 Agent 的写操作串行化。一次切换先读当前文件并检测外部修改，再计算补丁与备份，写入私有临时文件，验证后原子发布；只有所有目标文件成功发布才更新当前供应商指针。中途失败恢复备份；进程在多文件操作中断时，下次启动依据操作记录恢复到一致状态。外部程序在用户确认前修改了相关字段时，停止写入并提示重新读取；无关字段仍尽量保留。Mobi 的 Hook 安装或自动修复不能与切换互相覆盖。

## 余额查询与桌宠空间

余额查询以供应商适配模板为入口。内置模板只请求其明确列出的 HTTPS 主机；自定义地址需要用户明确填写，凭据仅发往该地址。首阶段支持 CC Switch 已提供且能在本机验证的模板；自定义供应商若无查询规则，显示「暂不支持查询」。第二阶段提供受限的请求字段与响应字段映射，不执行用户输入的任意 JavaScript。查询结果统一为金额余额或套餐剩余额度，并包含查询时间和错误状态。桌宠空间使用当前启用供应商的结果；一个 Agent 有多个供应商时，不把其他账户的余额误放到当前 Agent 卡片中。用户可手动刷新，后台刷新有时间间隔与超时限制。

## 验证标准

- 在测试配置目录中添加、编辑、删除和切换 Claude Code、Codex 供应商，实际文件与当前状态一致；切回原配置后原登录及 Mobi Hook 仍可用。
- 带注释、MCP、Hook 和自定义字段的配置文件经过切换后保持这些内容；外部修改、无效配置、写入失败和进程中断均不会留下假「已启用」状态。
- 密钥不出现在 IPC 列表、页面快照、日志和默认导出中；不安全的 Linux 存储后端不能静默保存密钥。
- 余额与额度可区分来源、单位、时间和过期状态；无查询能力时不显示金额。
- 页面与桌宠空间的自动化测试、主进程配置适配器测试、完整项目测试和手动桌面验证通过后，才宣布对应交付阶段完成。
